# v0.1.4 配速修复与跑步界面调整

## 配速

实时配速与本次平均配速分开。之前实时 GPS 配速为空时，跑步页会回退到总时长/总距离的平均配速，因此停下来后仍显示数值。该回退已删除，平均配速仅在历史、分析与总结中使用。

实时配速使用 GPS 速度和最近五秒的连续 GPS 位移确认：至少三秒的窗口、多个移动路段、足够净位移以及合理的轨迹方向，才显示配速；不使用步幅或计步估算。静止漂移、单次坐标跳变和不可靠速度不直接显示为运动配速。首次开跑或重新起步需要约三秒确认，信号不佳时可能更久。

接收器报告低速/静止、最新位置不再移动、暂停、结束或关闭 GPS 时清除实时配速；超过三秒没有有效 GPS 更新时不再显示旧配速。停止但 GPS 仍报告噪声速度时，需等待短窗口确认静止。未知/静止状态显示 `--`。

距离保存规则保持：仅记录原 GPS 距离通道，不改变累计距离和历史平均配速的计算。

## 跑步界面

距离和实时配速放在同一行，实时配速位于距离右侧，运动时间继续在下方独立展示。数值按可用宽度与字体设置适配；节拍 BPM 在下方单独显示。

新增回归覆盖静止 GPS 抖动、持续运动、运动后停止、暂停/恢复、GPS 关闭、定位更新过期、单点跳变、无速度字段及速度精度不足，并检查小屏幕的指标位置与实时配速显示。

版本 `0.1.4-native-test`，versionCode 5。新 GPS 过滤需在真机上复测站立与起步行为；此前 v0.1.3 的真机反馈不等同于本次修复已验证。

验证：39 项 JVM/Robolectric 测试通过，编译与 Lint 通过（0 错误、17 条提示）。已检查 360×640 跑步界面中有实时配速和无实时配速的截图。
